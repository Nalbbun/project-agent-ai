Executive Summary

AI 멀티 에이전트
실무 설계 및 운영 전략

단일 거대 모델에 의존하지 마십시오. 본 설계안은 작지만 강력한 3B 이하 모델(SLM)을 역할별로 배치하고, SFT 선행 및 GRPO 최적화를 통해 전문적인 소프트웨어 제작 AI 파이프라인을 구축하는 전략을 제시합니다.

가장 현실적인 1줄 전략
범용 3B 1개 + 코드 1.5B 1개 + 역할별 LoRA + SFT 선행 → 이후 GRPO + Tool Use + RAG

🔄 에이전트 협업 워크플로우

사용자의 자연어 요구가 실제 소프트웨어로 만들어지기까지, 각 전문 에이전트가 순차적/반복적으로 협업하는 구조입니다. 아래 역할 카드를 클릭하여 각 에이전트의 상세 과업과 입출력 데이터를 확인하세요.

🧠 권장 SLM (Small Language Model) 전략

모든 역할에 단일 거대 모델을 사용하는 대신, 특정 목적에 특화된 3B 이하 모델과 역할별 LoRA를 조합하는 것이 효율적입니다. 각 베이스 모델의 특성과 적합한 역할을 비교합니다.

Qwen2.5-3B-Instruct

공통 범용 베이스

구조화 출력(JSON/YAML) 및 긴 컨텍스트(32K) 안정성이 뛰어남.

적합: Architect, QA, SecOps

EXAONE 3.5 2.4B Instruct

한국어/영어 보조

영/한 이중언어(Bilingual) 문서화, 요구사항 정리, 질문 생성에 탁월.

적합: PM, Manager, (한국어 QA)

Qwen2.5-Coder-1.5B

코드 전용 베이스

소형이지만 코드 생성, 수정, 리팩토링에 특화. LoRA 분리 용이.

적합: Dev (FE / BE / DB)

📈 SFT에서 GRPO로 이어지는 학습 파이프라인

처음부터 RL(강화학습)을 적용하면 포맷 붕괴가 발생합니다. 반드시 SFT로 JSON/YAML 형식을 고정한 후, 자동 평가가 가능한 역할부터 GRPO(Group Relative Policy Optimization)를 적용해야 합니다.

Phase 1

SFT (Supervised Fine-Tuning) 선행

PM, Architect, Dev 역할 우선 학습. 가벼운 LoRA 어댑터를 통해 각 역할별 말투, 의사결정 방식, 무엇보다 JSON/YAML 출력 형식을 안정화합니다.

형식 안정화 역할 부여
Phase 2

Offline Eval 구축

역할별 검증기(Validator)를 통한 자동 평가 체계 구축. 평가셋(100~300개) 없이 GRPO를 진행하면 모델 개선 여부를 판단할 수 없습니다.

Schema Pass > 95% Task Success
Phase 3

GRPO (강화학습) 순차 적용

자동 평가가 쉬운 Dev(빌드/테스트 성공)와 QA(결함 탐지)부터 Reward 함수를 연결하여 GRPO를 적용합니다. 이후 Architect, PM, Manager 순으로 확장합니다. 정답을 외우는 것이 아닌 '행동 품질 최적화' 단계입니다.

추론 및 품질 향상 행동 최적화
Phase 4

Multi-agent Orchestration & Production

Manager 에이전트를 중심으로 전체 체인을 실행합니다. Tool Use(샌드박스, 보안 스캐너)와 RAG(사내 표준 문서)를 연동하여 실무형 시스템을 배포합니다.

Tool 연동 vLLM 배포

🎯 GRPO 보상(Reward) 가중치 설계

역할마다 성공을 측정하는 기준이 다릅니다. 각 에이전트의 목표 지향적 행동을 유도하기 위해 보상 가중치를 다르게 설계해야 합니다. (공통: 형식 준수 및 Hallucination 패널티)

역할별 보상 체계 보기

인사이트: 코딩 에이전트는 '빌드 성공'과 '테스트 통과' 등 절대적 실행 지표가 보상의 핵심을 이룹니다.

Dev 에이전트 보상 가중치 (R_dev)

⚙️ 배포 아키텍처 및 Tool Layer 연동
